# 持久故障内部实现

`recovery::incidents` 保存监控检查点、故障轮次和人工确认。它不轮询来源、不匹配规则、不调度审批或修复；监控调度由 Host 负责。领域关系见 [恢复领域](../README.md)。

## 源码导航

父层 [incidents.rs](../incidents.rs) 导出数据接口约定，保留 `IncidentStore` 的私有字段、日志事件和公开读写入口。

| 文件 | 职责 |
| --- | --- |
| [contract.rs](contract.rs) | 信号、故障、确认、来源检查点、容量及错误接口约定 |
| [storage.rs](storage.rs) | 文件所有权、排他锁、回放、同步追加、写失败停用与显式关闭 |
| [transitions.rs](transitions.rs) | 实时与回放共用的纯迁移准备、批内有序归并和同步后的安装 |
| [validation.rs](validation.rs) | 文本、JSON 复杂度与编码字节数的有界校验 |
| [paths.rs](paths.rs) | 外部目录、链接、硬链接及打开对象身份检查 |

## 提交与故障语义

`commit(MonitorCommit)` 在一条 JSONL 事务中提交完整检查点和有序信号批次。每个监控来源的提交序号从 1 开始、逐次加 1；只有最近一次完全相同的提交可幂等重试，不追加日志或覆盖其后的人工确认。检查点、故障记录和内存游标都在日志同步成功后才变化。

故障按 `(monitor_id, target_id, rule_id, kind)` 归并。已有未解除故障轮次收到 `Active` 时增加异常样本数 `occurrences`；`Clear` 解除该轮次；`Unknown` 只更新观察，不解除故障。不存在活动故障轮次时，`Clear` 或 `Unknown` 不创建故障；解除后再次 `Active` 创建新 ID。同一批中的信号依序处理，保留先异常、后解除、再复发的独立轮次。独立故障轮次的计数由 [恢复流程](../workflow/service/README.md) 维护。

`checkpoint` 读取来源游标；`get`、`list` 和 `map_records` 读取故障记录或其只读查询结果。`acknowledge` 要求当前记录版本号且记录仍为 `Open`，只登记已认证调用方的关注与审计归属，不能解除故障或产生许可。显示时间不会因调用方时钟回退而倒退，排序与提交顺序仍以持久序号为准。

## 配置与容量

可信调用方通过 `IncidentStore::open(path, config)` 显式传入配置。`IncidentStoreConfig` 支持序列化与反序列化，缺失字段使用默认值、未知字段被拒绝；公开 `validate` 与 `open` 使用相同范围检查。配置加载和服务装配不在本域。

| 字段 | 默认值 | 有效范围 |
| --- | --- | --- |
| `max_incidents` | 10,000 | 1..=100,000 个历史故障轮次 |
| `max_monitors` | 256 | 1..=4,096 个监控来源 |
| `max_journal_bytes` | 64 MiB | 1..=1 GiB |

一批最多 128 个信号，完整检查点最多 128 KiB，单条证据最多 16 KiB，确认说明最多 4 KiB，单条 JSONL 最多 512 KiB。容量或输入错误拒绝整个事务，不能推进检查点或静默删除历史。

## 持久恢复与生命周期

存储持有单写入者锁，实时提交和恢复使用相同迁移检查。回放拒绝非法顺序、未知格式、重复事务、完整损坏及末尾残片，不截断日志。写入或同步失败保留先前内存事实并停用后续写入；可信调用方检查存储后才能重新打开。

`open` 要求源码外的绝对日志文件路径，并核对打开对象身份及长度。Windows 通过拒绝删除共享的目录和文件句柄固定路径，拒绝 reparse point 与硬链接；Unix 检查祖先、设备/inode 身份和链接数。此保护依赖可信本机身份与目录权限，不能隔离恶意同账号或同进程代码。

`close` 释放文件和目录锁，保留只读历史，禁止继续提交或确认。内部迁移准备和安装只在故障存储域可见；其他模块通过公开接口约定读取或提交。

测试入口与私有存储测试登记见 [集中测试](../../../tests/README.md)。
