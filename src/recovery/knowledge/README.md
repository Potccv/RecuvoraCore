# 修复经验与候选脚本

`recovery::knowledge` 提供有界、单写入者、可恢复的知识库日志与精确条件检索，保存候选脚本、可信流程提交的操作结果和业务验证引用。它不运行脚本、不授予许可、不代替故障、审批或修复日志。领域关系见 [恢复领域](../README.md)。

## 源码导航

[mod.rs](mod.rs) 提供公开入口，重导出领域接口约定与 `KnowledgeStore`；存储字段和日志事件由 [storage.rs](storage.rs) 维护，内部模块共同维护一份知识库权威记录。

| 文件 | 职责 |
| --- | --- |
| [contract.rs](contract.rs) | 不可变脚本、候选、案例、检索条件及可信验证断言 |
| [validation.rs](validation.rs) | 文本和集合上限、适用条件及验证关联检查 |
| [source.rs](source.rs) | 外部只读知识库的候选修复经验、来源绑定与隔离过滤 |
| [maintenance.rs](maintenance.rs) | 无脚本文本的运行状态查询摘要、完整检查点导出和重放校验 |
| [storage.rs](storage.rs) | 单写锁、同步日志、幂等写入、重放、禁用与检索 |
| [paths.rs](paths.rs) | 存储路径隔离、文件身份和链接检查 |

## 候选、版本与案例

`upsert_candidate` 以候选 ID 幂等登记：相同 ID 只能重试完全相同的候选，不能覆盖已验证状态；不同内容需新 ID。脚本 `(id, version)` 在整个存储中不可变，涵盖文本、语言、平台、前提和生成时的 Harness（AI 服务接入）及会话归属，修改内容需新版本。

脚本文本最多 32 KiB，语言标签接受 `powershell`、`sh`、`python`；标签不证明执行器支持相应语言或平台。`validate_script` 检查文本上限、必需前提及已有版本内容一致性，不保留新版本身份、不证明当前适用性、不授予许可；写入时仍重复检查不可变约束。具体脚本和案例属于运行数据，不放入本库源码或配置模板。

`record_outcome` 以案例 ID 作为全局幂等键。相同结果重试不追加记录、不覆盖后续失败；同一案例 ID 携带不同结果或归属被拒绝。修复经验提交结果不能证明外部动作有无执行，保存失败的流程重试规则见 [恢复流程](../workflow/service/README.md)。

记录状态为 `Candidate`、`Verified`、`Failed`、`Unknown`、`Disabled`。任一失败、Unknown 或人工禁用永久隔离该不可变脚本版本在所有案例中的自动检索；后续同版本成功可保留审计，但不能解除隔离。新脚本版本需重新验证。

每次方案均可保存为案例，是否达到重复故障阈值不决定留存。`KnowledgeCandidate.reusable` 是可信流程计算的复用检索资格，缺失字段反序列化为 false，不代表审批或许可；模型不能自行扩大其含义。独立故障轮次与异常样本的区别和资格计算由 [恢复流程](../workflow/service/README.md) 维护。

## 精确检索与排序

`search` 返回已验证、未隔离且适用的修复经验记录，包含普通方案，供诊断使用。`search_reusable` 使用相同匹配规则，在结果限额前额外过滤 `reusable=true`，供优先脚本复用。两种查询都不能代替执行前的当前适用性审核和正式许可。

候选条件与脚本前提必须全部在查询中精确匹配；关键词为大小写敏感的精确 AND 匹配，不以模糊相似度授权。条件最多 32 项、关键词最多 32 项，一次最多返回 100 条。

隔离、适用性与复用资格过滤先于排序和限额。匹配记录按其全部案例中的可信验收次数、最近可信验收时间、精确条件覆盖数依次降序比较，最后按候选 ID 升序稳定排序；条件覆盖对候选条件与脚本前提的键去重计数。

## 外部只读知识库

`KnowledgeSource` 是 Host 实现的只读业务接口，暴露稳定逻辑 `identity` 和接受领域 `KnowledgeQuery`、`Cancellation` 的异步 `query`。Host 负责路由、聚合、外部响应分配上限与取消处理；Core 不解释供应商、连接地址、传输方式、索引或配置。来源绑定与流程回退见 [恢复流程](../workflow/service/README.md)。

`KnowledgeProposal` 只携带 `source_id`、候选和来源证据引用，不接受成功状态或可信验收断言。`validate_external_candidates` 校验 Host 绑定身份、查询条数上限、全部有界字段和总计最多 4 MiB 的响应；字段检查先于序列化额外分配。

候选或脚本版本的内容冲突、重复候选 ID、无效证据拒绝整个批次；不同内容不得复用已有脚本 `(id, version)`。不适用或已在本地隔离的版本被过滤。接受结果按精确条件覆盖数降序、候选 ID 升序排列。

通过校验的候选强制 `reusable=false`，合并去重的候选证据、来源证据和 `knowledge-source:<identity>` 标记。结果仅作为诊断输入，不写本地权威日志、不生成 `Verified`、不进入优先脚本复用。来源不能提供结果写入工具或可信验收工具；诊断生成的自身方案仍经过正常审核、一次许可、执行和业务验收。

## 可信业务验证边界

`Verified` 必须有 `TrustedBusinessVerification::attest` 创建的参数，绑定相同操作、目标、脚本版本、可信验证者、非空证据引用与验证时间。该参数没有 `Deserialize` 实现，模型候选没有状态字段；解析模型 JSON 不能产生成功断言。持久化的 `BusinessVerificationRecord` 只是只读查询结果，不能替代可信参数。

`attest` 是经过认证的嵌入应用对独立业务验证的显式断言，不进行证据真实性校验、身份认证或密码学证明。嵌入应用须限制写入 API、保存可追溯证据并绑定验证者身份；不能把构造器或结果写入接口作为模型工具，不能从模型回答、脚本退出码、文件读回或暂时无错误日志直接断言成功。修复经验记录仅保存引用，不读取或验证引用内容。

## 存储配置与恢复

`KnowledgeStore::open` 接受源码外的绝对文件路径和可信 `KnowledgeStoreConfig`。配置支持序列化与反序列化，缺失字段使用默认值、未知字段被拒绝；公开 `validate` 与 `open` 使用相同容量范围。配置传入恢复流程的入口见 [恢复流程](../workflow/service/README.md)。

| 字段 | 默认值 | 有效范围 |
| --- | --- | --- |
| `max_records` | 1,024 | 1..=100,000 个候选 |
| `max_cases_per_record` | 128 | 1..=1,024 个案例 |
| `max_journal_bytes` | 64 MiB | 1..=1 GiB |

单条 JSONL 最多 256 KiB。事件写入并同步成功后才发布内存；写入失败停用后续写入。记录、案例或字节容量耗尽拒绝整个事务，不自动清理历史。完整损坏、末尾残片、格式版本不受支持、序号错误或重复已提交事件均拒绝恢复，不截断日志。

存储拒绝链接和替换身份，持有独占写锁。路径检查保护本库编译源码位置；嵌入应用仍负责自己的源码、安装目录、配置和证据。`close` 释放锁、禁止写入、保留只读快照。共享存储只由一个实例持有并互斥访问，外部 Harness 调用期间不持有存储锁。此信任边界不隔离恶意同账号或同进程代码。

## 查询摘要与离线压缩

### 查询摘要

`projection` 返回日志字节与容量、候选/脚本/案例/隔离版本数量、各状态数量和写入可用性。`inspect` 按 ID 使用稳定游标分页，并按状态/隔离过滤，一页最多 100 条；返回摘要、脚本身份与字节数、可信验收次数和时间、禁用归属，不返回脚本文本或完整验收证据。查询摘要中的 `reusable` 和 `Verified` 不构成当前许可。

### 完整检查点与压缩

`export_compacted` 返回没有公开构造器或 `Deserialize` 实现的 `CompactJournal`，记录来源提交序号及字节数、输出字节数和事实数量，`as_bytes` 提供完整 v2 检查点日志。导出要求可靠的持锁日志持有者，并核对源文件身份与长度；关闭、写入失败或来源已变化的存储拒绝导出，不能使用过期或不确定的内存快照迁移。

检查点按每条最多 256 KiB 分块保存全部候选和案例，保留所有脚本版本内容、案例幂等键、记录版本号、禁用归属、历史失败/Unknown 和永久隔离事实。回放重复候选、案例、可信验收绑定、时间、不可变版本与禁用校验，从全部事实推导状态和隔离，再核对声明的状态、记录版本号、数量与完整提交；缺失提交、遗漏候选/案例、重复身份或不一致声明拒绝恢复。

格式 1 的普通事件日志可读取，检查点及其后续事件使用格式 2；反复压缩保留相同权威事实，不放宽隔离或许可。压缩只减少事件封装字节，不降低候选数或单候选案例数。检查点输出超出配置字节容量时拒绝导出，可信调用方可使用明确授权的更高容量配置。

Core 只导出检查点，不替换运行文件。Host 的冻结、源比对、关闭/重开、离线安装、配置校验、切换与备份流程见 [领域维护](../../../docs/domain-maintenance.md)。检查点沿用受保护本地日志的信任边界，不是密码学证明；外部来源不能提交检查点来替代诊断候选或本地验收。

## 范围与验证

本域不实现全文日志归档、向量索引、语义诊断、平台脚本执行或业务验证器。集中测试及维护测试子模块的映射见 [测试说明](../../../tests/README.md)，不表示真实节点脚本或业务恢复验收。
