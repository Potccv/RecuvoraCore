# 实现状态与验证范围

当前 `recuvora-core` 0.2 是单包纯领域库。公开顶层仅 `operation` 与 `recovery`；产品源码不执行文件读写、文件锁、网络调用、系统时钟、线程调度或异步任务。持久化、原子提交、运行生命周期和实际外部能力由可信 Host 负责。

## 已实现

| 能力 | 当前实现 |
| --- | --- |
| 提交协议 | 纯 `Prepared`，增量输入与历史摘要绑定领域、配置和版本；可靠 Host 确认后才返回新状态与效果 |
| 故障 | `IncidentLedger` 的检查点/信号原子计算、幂等、归并、独立轮次、关注与历史验证 |
| 审批 | `ApprovalLedger` 的当前硬政策、审核模式/身份/期限、一次许可、目标互斥、Unknown及显式重启恢复 |
| 知识 | `KnowledgeState` 的不可变脚本、案例幂等、可信验收、永久隔离、精确检索、外部候选限制和完整数据输出 |
| 恢复流程 | 原方案审批关联、诊断预算、提交后派发、执行与业务验收区分、结果核实、显式恢复及受限重新诊断 |
| 旧历史导入 | 完整审批/工作流历史校验、原 revision 与身份保留、未知消费封锁、Publishing 精确续交及无执行效果导入 |
| 经验交付 | 任务结果与待交付记录同提案提交，失败/Unknown先保存本地隔离，同候选交付按产生顺序推进 |

接口、职责和迁移边界分别见[源码导航](../src/README.md)、[架构](architecture.md)和[Host 接入迁移](host-boundary-migration.md)。

## 已知问题

CORE-001 至 CORE-004 已在领域实现和固定回归范围内关闭。下列状态不代表外部 Host 已完成接口迁移、持久提交或实际业务恢复验收；接入变化见[Host 边界迁移](host-boundary-migration.md#当前增量提交接口)。

### CORE-001 · 已关闭 · 增量绑定与结构共享

四个领域的提交改为绑定先前完整历史的 SHA-256 摘要及完整新输入，初始摘要绑定原配置。聚合使用共享有序集合、历史向量及不可变记录，不再为每次提案编码全历史、深复制整个聚合或保留历次完整快照。去重提交身份使用有序索引；故障完全重复检查在请求编码前返回。Host 通过 `latest_entry()` 保存增量，`entries()` 仅在需要时复制导出完整历史。契约见[领域维护](domain-maintenance.md#增量绑定与历史导出)。

固定回归覆盖持续健康轮询、故障增长、审批积累、恢复任务积累和知识候选积累，限制请求大小并验证完整重放。摘要或原配置冲突、跨历史分支回执、非法历史均被拒绝；恢复不重发许可，故障轮次、案例幂等及永久隔离继续保留。规模结果见下文。全部安全历史仍保留，内存随事实增长；互斥和轮次检查仍可能扫描记录，没有通用历史裁剪或可安装检查点，也不承诺全部操作常数成本。

### CORE-002 · 已关闭 · Harness 结果必须关联审核尝试

普通 `ApprovalChange::Assess` 在实时及历史共用校验中均返回结构化错误。Host 必须先提交 `BeginReview` 并确认取得 `ReviewAttempt`，再用 `AssessAttempt` 返回结果。人工决定仍通过当前政策及记录版本校验。完整旧历史可经专用 `ApprovalImport` 入口按原规则导入；普通入口仍拒绝旧 `Assess`，专用入口也不补造缺失审核尝试或重新发出许可。

固定回归拒绝未登记尝试的实时结果、恢复后的旧回调及审核截止时间到达后的结果，同时保留有效审核、人工接管、硬政策、请求有效期和一次许可覆盖。原有审批和恢复流程正常路径已改用已提交审核尝试，见[审批测试](../tests/approval.rs)与[恢复测试](../tests/recovery.rs)。

### CORE-003 · 已关闭 · 知识容量受校验扩展

`KnowledgeCommand::ExpandCapacity { expected, target }` 绑定当前配置、目标配置、版本与先前完整历史，只允许合法范围内单调增容。扩容仍经过提案、Host 原子提交和确认，不改变领域记录、案例、脚本或隔离，不产生执行效果。重放从原配置开始，按顺序应用迁移；重复提交身份或过时配置拒绝。详细限制见[知识容量接口](../src/recovery/knowledge/README.md#逻辑容量与查询摘要)。

固定回归覆盖容量已满、原配置重放、丢弃未确认提案、提交后重启重放、增容后继续记录、非法缩容、无效容量、重复迁移和提交身份冲突，并验证 Unknown、失败、禁用、全局案例幂等和不可变脚本事实保留。合法容量上限仍然存在，不提供无限增长或丢弃安全事实的出口。

### CORE-004 · 已关闭 · 外部候选先规范化再比较身份

来源身份、字段和输入字节校验后，候选先强制 `reusable=false`，合并去重并排序全部证据及来源标记，再与本地不可变候选比较。相同 proposal 首次登记后可以重复接入；脚本、候选内容或来源的真实冲突继续拒绝整批输入。隔离与适用性过滤保持不变。

固定回归覆盖重复接入、证据顺序变化、重复附加 Host 来源标记以及真实身份和脚本冲突，见[知识测试](../tests/knowledge.rs)。

## 已执行验证

使用 Rust 1.98.1 Windows GNU LLVM 工具链，通过[现有 Windows 检查入口](../scripts/windows/README.md)执行格式检查、全部目标 Clippy（`-D warnings`）、74 项集成测试和文档测试命令。74 项由提交协议 3 项、故障 11 项、审批 19 项、知识 14 项、恢复流程 27 项组成。库单元测试与文档测试各有 0 个可执行测试。全部领域测试使用显式业务时间和内存状态；文档已核对相对链接、锚点、接口名称与迁移说明。

回归覆盖未提交状态不变、错误回执拒绝、原操作及政策绑定、一次许可不重发、审核尝试期限及重启失效、恢复前阻塞、Unknown 永久隔离、两阶段核实时间推进、缺失任务回执的核实出口、经验交付失败独立于业务终态及交付顺序，并包含上述四项问题的固定回归。入口见[测试导航](../tests/README.md)。

旧历史专项回归覆盖随机任务身份、原操作与 revision、诊断预算和轮次、缺失或篡改历史拒绝、无 Consume 的不确定执行意图封锁、Publishing 的原案例时间和幂等、Unknown 独立核实后仍永久隔离、终态案例关联及导入后任务 ID 碰撞保护。

## 接入与验证限制

Core 不实现数据库或文件持久化、分布式锁、证据真实性验证、认证、实际脚本执行或进程停止监督。提交回执与可信验收构造器是 Host 的断言；领域测试不证明外部事务、互斥或真实业务恢复。

Core 提供旧审批及工作流的完整历史纯校验与导入提案；物理旧文件读取、保护、安装和进程中断验收属于 Host。Core 测试不证明外部 Host 的接入。原物理存储与运行编排保留为项目外开发参考，不能视为已经适配新接口。原有本地文件、锁、压缩及运行时测试属于该参考实现，不作为当前纯领域测试的通过项。此次未执行 MSVC 链接验证，未重跑未改动的开发脚本专属回归。
