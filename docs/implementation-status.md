# 实现状态与验证范围

当前 `recuvora-core` 0.2 是单包纯领域库，公开顶层仅 `operation` 与 `recovery`。Core 计算领域提案；Host 提供可信输入、原子持久提交、目标所有权和实际执行。

## 当前能力

| 范围 | 实现 |
| --- | --- |
| 提交协议 | `Prepared` 绑定领域、配置、完整新输入、先前历史摘要与版本，Host 确认后安装状态和交付效果 |
| 故障 | `IncidentLedger` 保存信号与检查点、幂等归并、故障身份及历史校验 |
| 审批 | 当前硬政策、完整操作、审核尝试与期限、一次许可、同目标互斥及 Unknown 核实 |
| 恢复 | schema 2 的单一 `StartRepair` 流程：故障和稳定条件匹配经验一起交给已授权 Harness；完整命中数与按预算附带的经验分别表达 |
| 动作 | 中立 `RepairArtifact` 保存类型、完整载荷、前提和来源；单会话最多一个动作，提交后才可派发 |
| 经验 | 单一 `RepairExperience` 集合，先筛选排序引用再复制最终结果、不可变产物、幂等登记、失败与 Unknown 永久版本隔离 |
| 总结与交付 | 独立 `ExperienceJob` 保存实际动作、总结及三态脚本化评估；候选不自动成为可信执行事实 |
| 当前历史恢复 | 使用实时校验重放；显式恢复保留审批期限、预算与原操作，中断执行进入 Unknown，不重发许可 |

不提供旧配置、旧诊断/脚本复用流程、旧案例模型或旧历史导入兼容。配置和事件必须满足当前协议。脚本语言、平台、源代码解释及执行器配置由 Host 管理。

接口关系见[架构](architecture.md)、[恢复参考](recovery.md)、[知识模块](../src/recovery/knowledge/README.md)及[Host 接入](host-boundary-migration.md)。

## 验证范围

使用 Rust 1.98.1 Windows GNU LLVM 工具链，通过现有 Windows 检查入口执行格式、全部目标 Clippy（`-D warnings`）、70 项集中测试和文档测试命令。测试包括提交 3 项、故障 11 项、审批 16 项、知识 12 项、恢复 28 项；库单元测试和文档测试当前均为 0 项。集中回归关注完整提交绑定、无确认无效果、当前政策及审批尝试、一次许可、当前历史恢复、Unknown 两阶段核实、具体动作精确绑定、失败隔离与独立经验交付。边界回归覆盖动态观察变化、稳定条件变化、第五条小经验补入、完整请求恰好 32 KiB 与超出一字节的筛选，以及命中数、顺序、重复身份和适用条件被篡改的历史拒绝。测试入口见[测试导航](../tests/README.md)。

规模回归验证故障、审批、恢复任务和经验累积时的有界提交请求及完整重放；没有重新测量长期内存、外部吞吐或生产性能。全部历史仍被保留，内存随事实增长；不提供历史裁剪、任意检查点安装或无限容量。

## 接入与验证限制

经验按可信稳定条件与关键词精确匹配，没有语义检索。动态观察保留在审计中，不自动成为经验适用条件；超过请求预算的经验整条省略，后续较小条目仍可选入。脚本化候选只是报告产物，没有自动晋升或绕过新审批的执行入口。动作失败或 Unknown 的本地隔离先与恢复变更提交，知识保存失败不会丢失该事实。

Core 不实现物理存储、文件锁、网络、系统时钟、调度、认证、实际执行器、进程监督或证据真实性验证。提交回执和可信经验断言是 Host 的声明；领域测试不证明 Host 持久性、分布式互斥、真实执行者停止或实际业务恢复。未执行 MSVC 链接验证。
