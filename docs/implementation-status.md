# 实现状态与验证范围

当前 `recuvora-core` 0.2 是单包纯领域库。公开顶层仅 `operation` 与 `recovery`；产品源码不执行文件读写、文件锁、网络调用、系统时钟、线程调度或异步任务。持久化、原子提交、运行生命周期和实际外部能力由可信 Host 负责。

## 已实现

| 能力 | 当前实现 |
| --- | --- |
| 提交协议 | 纯 `Prepared`，请求绑定完整逻辑输入、领域和版本；可靠 Host 确认后才返回新状态与效果 |
| 故障 | `IncidentLedger` 的检查点/信号原子计算、幂等、归并、独立轮次、关注与历史验证 |
| 审批 | `ApprovalLedger` 的当前硬政策、审核模式/身份/期限、一次许可、目标互斥、Unknown及显式重启恢复 |
| 知识 | `KnowledgeState` 的不可变脚本、案例幂等、可信验收、永久隔离、精确检索、外部候选限制和完整数据输出 |
| 恢复流程 | 原方案审批关联、诊断预算、提交后派发、执行与业务验收区分、结果核实、显式恢复及受限重新诊断 |
| 经验交付 | 任务结果与待交付记录同提案提交，失败/Unknown先保存本地隔离，同候选交付按产生顺序推进 |

接口、职责和迁移边界分别见[源码导航](../src/README.md)、[架构](architecture.md)和[Host 接入迁移](host-boundary-migration.md)。

## 已执行验证

使用 Rust 1.98.1 Windows GNU LLVM 工具链，通过[现有 Windows 检查入口](../scripts/windows/README.md)执行格式检查、全部目标 Clippy（`-D warnings`）、56 项集成测试和文档测试命令。56 项由提交协议 3 项、故障 9 项、审批 14 项、知识 11 项、恢复流程 19 项组成。库单元测试与文档测试各有 0 个可执行测试。

回归覆盖未提交状态不变、错误回执拒绝、原操作及政策绑定、一次许可不重发、审核超时和迟到回调、恢复前阻塞、Unknown永久隔离、两阶段核实时间推进、缺失任务回执的核实出口、经验交付失败独立于业务终态及交付顺序。测试使用显式时间和内存领域状态，入口见[测试导航](../tests/README.md)。

## 接入与验证限制

Core 不实现数据库或文件持久化、分布式锁、证据真实性验证、认证、实际脚本执行或进程停止监督。提交回执与可信验收构造器是 Host 的断言；领域测试不证明外部事务、互斥或真实业务恢复。

当前不提供旧文件日志的自动导入，也未修改或验收外部 Host 的接入。原物理存储与运行编排保留为项目外开发参考，不能视为已经适配新接口。原有本地文件、锁、压缩及运行时测试属于该参考实现，不作为当前纯领域测试的通过项。此次未执行 MSVC 链接验证，未重跑未改动的开发脚本专属回归。
