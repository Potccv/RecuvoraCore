# 实现状态

版本 0.2.0，单 Cargo 库包，公开顶层模块为 operation 和 recovery。

已实现 RecoveryEngine 完整恢复编排和 RecoverySession 原子聚合：故障接收、经验匹配、审批、一次执行、独立验收、Unknown 核实、只读总结和经验交付。创建操作及审批、许可消费及授权、回执及审批完成、结果核实、经验交付分别以完整聚合提案确认。

支持中立错误报告受理：原始日志及有界结构化证据完整进入问题、任务与聚合，不校验日志活跃性或时效；`active` 和 `received` 仅为持久历史保留序列化兼容。完整报告身份去重并拒绝内容改写，目标条件采集、审批、一次许可、执行和独立验收继续生效。报告格式和来源证据要求见[恢复流程](workflow.md)。

底层保留稳定条件合并、精确匹配、完整命中数、32 KiB 内最多四条整条经验选择和经验构造。失败与 Unknown 的实际动作隔离随结果提交；候选脚本不继承业务成功，不自动晋升。

本库通过注入接口调用外部能力，不实现具体文件读写、锁、网络、系统时钟、调度或进程监督。故障采集台账与物理可靠性由调用方提供。

## 验证范围

使用 Rust 1.98.1 Windows GNU LLVM 工具链，通过格式、严格 Clippy、83 项领域测试及 1 项文档示例。引擎回归覆盖调用顺序、人工等待、失败授权的原子性、审核上下文提交绑定、过期批准、重启无许可、Unknown 不重派和经验独立重试，以及错误报告原文和结构化证据保留、全部兼容标志组合均可受理和匹配经验、身份与 revision 继续约束授权及派发、无审批不执行、完整内容去重、首次受理期间的确认版本增长、字节和嵌套边界、目标条件预留和默认序列化绑定。测试归属见[测试导航](../tests/README.md)。

没有旧历史兼容、语义经验检索、候选脚本自动晋升或多步变更会话。领域测试不证明调用方的真实持久化、跨实例锁、外部执行器或业务恢复。
