# 架构与可信 Host 边界

Core 是单 Cargo 库包 `recuvora-core`，公开顶层模块只有 `operation` 与 `recovery`。Core 根据已验证领域状态、可信配置和输入事实，计算状态迁移及外部操作意图。它不保存文件、不连接存储、不读取时钟、不调度任务，也不主动调用审核、执行或验收服务。

## 职责分工

| 角色 | 职责 |
| --- | --- |
| Core | 基于可信稳定条件的经验匹配、统一 Harness 请求、完整动作绑定、硬政策与一次许可、结果核实、独立经验总结状态及动作版本隔离 |
| Host | 认证、配置和时间输入、完整历史加载、原子持久提交、当前事实并发校验、目标所有权、外部调用与运行生命周期 |
| 存储与查询模块 | Host 选择的持久保存、事务、索引、备份、归档及检索基础设施 |
| 节点或外部能力模块 | 采集、目标检查、实际 external action、执行停止确认及独立业务验收 |
| UI | 展示已提交事实、提交人工意愿；不自行产生审批、许可或成功事实 |

Harness 指 AI 服务接入；`execution_harness`、`executor_id` 等逻辑身份参与规则绑定与审计。连接地址、传输方式、节点工作区和能力路由由 Host 管理，不进入 Core 配置。模型、经验候选和外部响应只是输入证据，人工决定也必须通过硬政策校验。

## 纯领域接口

| 接口 | 输入与输出 |
| --- | --- |
| `IncidentLedger` | 观察提交、人工关注及已提交历史，计算故障和检查点提案 |
| `ApprovalLedger` | 完整操作、当前政策、审核与结果事实，计算审批提案及确认后的一次许可 |
| `KnowledgeState` | 可信 `RepairExperience` 与容量命令，计算经验提案、精确检索、不可变产物和永久隔离 |
| `RecoveryState` | 故障、观察、经验、审批、动作与结果事实，计算统一 Harness 请求、结果及独立总结提案 |
| `Prepared`、`CommitRequest`、`CommitReceipt` | 待提交结果、完整输入绑定及可信 Host 的可靠提交确认 |

领域细节由[源码导航](../src/README.md)下的所属 README 维护，接入顺序见[Host 接入](host-boundary-migration.md)。恢复配置只接受当前 schema 2；领域恢复校验当前历史，不提供其他协议或旧历史的兼容导入。

## 提交边界

一次计算不会改变调用方持有的旧聚合。Core 返回 `Prepared`；Host 在正确的聚合范围原子比较 `expected_revision`，保存完整变更及提交身份，可靠成功后构造 `CommitReceipt::confirmed` 并调用 `confirm`。新状态及执行效果由确认结果交付。

`CommitRequest` 绑定提交 ID、领域、原记录版本、新记录版本和完整逻辑输入。相同 ID 携带不同领域或输入必须拒绝；内容相同也不能重复释放一次执行副作用。确认是可信 Host 的显式断言，不是认证或存储服务。发送到消息队列、写入缓冲区、超时或连接中断均不能证明可靠提交成功。

Host 负责加载完整可信历史；各领域恢复入口使用与实时迁移相同的校验，恢复本身不返回执行许可或自动派发。Core 无法从删减、重新编号且重新计算摘要的历史识别被隐藏的旧事实，也无法证明数据库提交或跨进程互斥已经发生。持久恢复、跨域提交和目标归属的具体义务见[领域维护](domain-maintenance.md)。

## 动作与结果

`RepairArtifact` 是提供方中立的不可变动作内容；Core 只校验通用格式、来源、前提、配置允许的动作种类及一次动作预算。Host 解释 `kind` 与 `payload`，负责选择和调用具体能力。执行前保存完整动作，执行回执必须绑定该内容；经验命中或总结候选都不授予执行权限。

Host 只处理可靠确认后的效果，完成外部调用后把结果作为新输入交回 Core。超时计时、取消、等待在途调用结束、调度重试和证据保存由 Host 完成；取消或断连不证明外部动作已停止。

执行回执、独立业务验收和经验交付是不同事实。Unknown 要求独立执行证据，不能根据业务健康推断原操作是否运行。恢复结果、实际动作隔离和待总结经验共同提交；总结与经验存储故障不会改变已经确认的业务终态。流程及具体限制见[恢复流程](recovery.md)。
