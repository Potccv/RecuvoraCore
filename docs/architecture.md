# 架构与可信接口

Core 是单 Cargo 库包 `recuvora-core`，维护恢复决策、具有最终效力的状态和稳定业务接口。服务启动与组合、外部能力和界面展示由相应角色负责。

| 角色 | 职责 |
| --- | --- |
| Core | 是否修复、方案选择、审核人、批准与执行许可、执行结果、验收结论、修复经验保存 |
| Host | 身份认证、配置、定时处理、服务组合、Harness/知识库/节点路由、HTTP、CLI，以及跨进程协议实现与规范 |
| 节点/插件 | 采集、目标检查、脚本执行、进程监督、业务验收，按 Host 协议独立接入 |
| UI | 展示具有最终效力的记录并提交人工决定；界面状态不产生事实或授权 |

Harness 指 AI 服务接入，用于调用外部 AI 服务并管理会话。Core 通过业务接口请求外部能力，独立维护审核规则、审批、一次性执行许可、任务阶段和知识库状态。外部返回内容是证据，不能直接改变具有最终效力的状态；人工决定也必须经过不可绕过的规则校验。

| 接口 | 可信调用方责任 | 接口约定 |
| --- | --- | --- |
| `RepairBackend` | Host 路由检查、诊断、审核、执行和验收；节点/插件完成外部能力 | [恢复流程与审批恢复](recovery.md) |
| `IncidentGuard` | 提供当前有效的故障状态与记录版本号（`revision`） | [样本与独立故障轮次](domain-maintenance.md#样本与独立故障轮次) |
| `TargetOwnership` | Host 统一目标别名并提供共享所有权管理 | [共享目标所有权](domain-maintenance.md#共享目标所有权) |
| `KnowledgeSource` | Host 绑定稳定来源身份并负责只读候选路由与聚合 | [知识库接口约定](../src/recovery/knowledge/README.md#外部只读知识库) |

逻辑 `execution_harness` 和 `executor_id` 参与规则绑定与审计；具体节点、节点工作区、连接地址和传输方式由 Host 解析，不进入 Core 配置。Core 不实现网络客户端、能力注册、定期监控、采集器、脚本执行器、配置加载或界面数据转换。

源码入口见[核心源码](../src/README.md)，当前能力与验证边界见[实现状态](implementation-status.md)。
