# 恢复业务架构

Core 使用 `RecoveryEngine` 推进恢复流程，通过 `RecoveryPlatform` 调用注入能力。`RecoverySession` 统一持有审批、任务和经验领域状态；调用方负责事实来源、存储事务和外部能力实现。

提供方保证错误报告的错误识别和实时性；Core 绑定报告身份、revision 和完整内容后进入经验匹配等恢复流程，不重复判断日志是否活跃。目标条件观察、审批授权和业务验收分别保留自身职责。

| 层次 | 责任 |
| --- | --- |
| engine | 业务阶段循环、能力调用顺序、聚合提案、独立总结重试 |
| approval | 硬政策、审核身份与期限、一次许可、Unknown |
| workflow | 任务迁移、证据绑定、执行预算、验收结果与交付工作 |
| knowledge | 精确匹配、可信经验、不可变产物与隔离 |
| planning / experience | 稳定条件、请求预算、经验构造纯函数 |
| operation | 中立产物和完整输入绑定的提交协议 |

## 调用与提交

调用方启动 `advance`，引擎根据状态决定下一步并调用注入接口。注入接口返回观察、审核身份、执行回执或验收证据，Core 判定对应业务变化。编排未来值由调用方运行时驱动，本库不启动线程或读取系统时间。

`SessionCommand::Start` 同时生成操作、申请审批并关联任务；`Authorize` 同时消费审批和授权执行；`Executed` 同时完成审批和记录回执；`CheckResult` 同时核实审批及任务；`Deliver` 同时保存经验及完成交付。每项操作只有一个外层提交确认点，内部领域转换不提前释放效果。

故障采集、认证、物理目标锁、可靠存储、实际派发和取消排空仍属于调用方。内存校验不能证明外部事实仍有效；能力实现必须保持[调用契约](calling-contract.md)规定的保护。

低层领域 API 支持独立审批等用途；完整自动恢复使用聚合引擎，不要求调用方串联多份领域历史。领域流程见[恢复流程](workflow.md)，纯算法见[业务参考](recovery.md)。
