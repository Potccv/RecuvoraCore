# 架构与可信 Host 边界

Core 是单 Cargo 库包 `recuvora-core`，公开顶层模块只有 `operation` 与 `recovery`。Core 根据已验证领域状态、可信配置和输入事实，计算状态迁移及外部操作意图。它不保存文件、不连接存储、不读取时钟、不调度任务，也不主动调用诊断、执行或验收服务。

## 职责分工

| 角色 | 职责 |
| --- | --- |
| Core | 故障归并与轮次、硬政策和审批、一次许可、恢复状态迁移、结果核实、经验适用性与永久隔离 |
| Host | 认证、配置和时间输入、完整历史加载、原子持久提交、当前事实并发校验、目标所有权、外部调用与生命周期 |
| 存储与查询模块 | Host 选择的持久保存、事务、索引、备份、归档及检索基础设施 |
| 节点或外部能力模块 | 采集、目标检查、诊断、实际外部动作、进程停止确认及独立业务验收 |
| UI | 展示已提交事实、提交人工意愿；不自行产生审批、许可或成功事实 |

Harness 指 AI 服务接入；`execution_harness`、`executor_id` 等逻辑身份参与规则绑定与审计。连接地址、传输方式、节点工作区和能力路由由 Host 管理，不进入 Core 配置。模型、知识候选和外部响应只是输入证据，人工决定也必须通过硬政策校验。

## 纯领域接口

| 接口 | 输入与输出 |
| --- | --- |
| `IncidentLedger` | 观察提交、人工关注及已提交历史，计算故障和检查点提案 |
| `ApprovalLedger` | 完整操作、当前政策、审核与结果事实，计算审批提案及确认后的一次许可 |
| `KnowledgeState` | 候选、可信案例与禁用命令，计算经验提案、精确检索及外部候选校验 |
| `RecoveryState` | 故障、观察、方案、审批与结果事实，计算恢复提案及确认后的外部操作意图 |
| `Prepared`、`CommitRequest`、`CommitReceipt` | 表达待提交结果、提交内容绑定及可信 Host 的可靠提交确认 |

领域细节由[源码导航](../src/README.md)下的所属 README 维护。旧的存储打开接口、`RepairBackend`、`IncidentGuard`、`TargetOwnership`、`KnowledgeSource` 运行接口不再是当前接入方式；版本迁移见[Host 接入迁移](host-boundary-migration.md)。

## 提交边界

一次计算不会直接改变调用方持有的旧聚合。Core 返回 `Prepared`；Host 在正确的聚合范围原子比较 `expected_revision`，保存完整变更及提交身份，可靠成功后构造 `CommitReceipt::confirmed` 并调用 `confirm`。新状态及需要执行的副作用由确认结果交付。

`CommitRequest` 绑定提交 ID、领域、原记录版本、新记录版本和完整逻辑输入。相同 ID 携带不同领域或输入必须被 Host 拒绝；内容相同也不能重复释放一次执行副作用。确认是可信 Host 的显式断言，不是认证或存储服务。发送到消息队列、写入缓冲区、超时或连接中断均不能证明可靠提交成功。

Host 负责加载完整可信历史；各领域恢复入口使用与实时迁移相同的校验，恢复本身不返回可执行许可或自动派发。Core 无法从删减、重新编号且重新计算摘要的历史识别被隐藏的旧事实，也无法证明数据库提交或跨进程互斥已经发生。持久恢复、跨域提交和目标归属的具体义务见[领域维护](domain-maintenance.md)。

## 外部动作与结果

Host 只处理可靠确认后的副作用，完成外部调用后把结果作为新输入交回 Core。超时计时、取消、等待在途调用结束、调度重试和证据保存均由 Host 完成；取消或断连不证明外部动作已停止。

执行回执、独立业务验收和经验交付是不同事实。Unknown 要求独立执行证据，不能根据业务健康推断原操作是否运行。恢复结果与经验待交付记录可以共同提交，经验存储故障不会阻塞已经确认的业务终态；失败隔离事实仍先保存在恢复领域。流程及具体限制见[恢复流程](recovery.md)。
