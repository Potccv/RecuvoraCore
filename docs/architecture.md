# 业务计算架构

Core 由输入驱动，每次调用独立计算结果，不保存任务、权限或交付状态。

| 入口 | 输入 | 输出 |
| --- | --- | --- |
| `knowledge::matching_experiences` | 精确条件、关键词、经验引用 | 稳定排序的匹配引用 |
| `planning::prepare_repair` | 故障、观察、描述性约束、经验引用 | 完整命中数和预算内经验组成的修复请求 |
| `build_experience` | 故障、稳定条件、明确结果、实际动作、证据、总结 | 修复经验 |

`operation::RepairArtifact` 是动作内容；`recovery::knowledge` 定义经验、结果和脚本化评估；`recovery::planning` 合并稳定条件并生成请求。详情见[源码导航](../src/README.md)。

## 计算边界

调用方保证故障仍有效、输入来源可信并满足执行条件。Core 不判定观察是否新鲜、审批是否有效、执行是否允许，也不生成需要确认的状态提案。相同业务输入得到相同结果。

`TargetBinding`、Harness 身份、委托和调用预算是请求携带的描述数据，不是授权配置或调度器。本库不解释具体脚本语言、平台或连接方式。`RepairOutcome` 是显式输入，不能根据模型总结或候选脚本推断成功。

Core 保留数据形状、稳定条件冲突和序列化预算检查，它们服务于可确定的计算结果，不承担权限与可靠性管理。数据及调用前提见[调用契约](calling-contract.md)。
