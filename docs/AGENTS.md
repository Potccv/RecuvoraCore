# 核心文档规范

继承[项目规范](../AGENTS.md)，本文件补充文档组织与验证规则。阅读入口见[文档导航](README.md)。

## 一项事实一个归属

| 文档 | 应包含 | 通过链接引用 |
| --- | --- | --- |
| 根 README | 项目定位、使用方式、能力概览、开发入口 | 领域算法、局部 API 和检查细节 |
| 根 AGENTS | 每次开发都适用的规则与所属文档入口 | 现行机制、长例子、变更故事 |
| 局部 AGENTS | 该目录独有的开发义务 | 根规则和其他目录规则 |
| 架构 | 职责关系、可信端口、权威事实归属 | 具体模块方法和存储细节 |
| 领域参考与模块 README | 自身 API、前提、行为、失败、格式校验及限制 | 其他领域细节和验证流水 |
| 开发指南与脚本 README | 分步骤开发路径，或所属脚本参数与行为 | 领域政策、设计推理和重复检查清单 |
| 测试导航与验证政策 | 测试目标归属、检查选择和证据含义 | 领域实现细节和重复验收数字 |
| 实现状态 | 当前能力、限制及已执行验证的范围 | 测试过程、对话或按日期排列的真实部署记录 |

- 新文档先确定所属目录与读者目标，再选择流程指南或参考；较长的操作流程与 API 查阅说明分别维护。
- 父级只介绍自身和直接子域的职责，详细内容链接所属 README。移动重复事实时保留必要的格式校验、授权和失败限制，不以删短为目标。

## 表达与示例

- 描述现行机制，直接写明谁调用、保存什么事实以及失败后会发生什么；不在常驻文档叙述 PR、对话、修改过程或已放弃方案。
- 业务叙述使用项目[阅读约定](../README.md#阅读约定)中的中文名称；API、字段、枚举、测试目标和命令保持源码中的准确名称，接口说明不得改变授权或持久恢复语义。
- 用 Rust API 表达库接入，不编造应用入口、认证、热加载或平台支持。操作员标识 `actor` 是审计归属，不等于身份认证；接口约定登记不产生授权。
- 明确物理存储、目录保护、原子事务和外部资源属于 Host；Core 的领域校验不能作为这些机制已经生效的证明。
- 每个自然段使用一个物理行，段落间留空行；列表、表格和代码块保持 Markdown 结构。事实和限制保持具体，避免长段重复或无依据的强调。
- 示例须与实际 API、字段和脚本参数对应，区分占位输入与可直接运行的命令；新增参考登记到[导航](README.md)。

## 文档检查

- 仓库内引用使用相对 Markdown 文件链接；检查目标和锚点可达，不以裸文件名代替导航。
- 校验目录、导出、API 名称、配置字段、格式版本和检查命令与源码一致；不得把纯文档改动写成已完成代码接入。
- 纯文档改动执行链接、格式与内容核对，不制造程序测试；实际检查记录与证据边界遵循[验证政策](testing.md)。
