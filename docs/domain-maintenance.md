# 领域维护与日志迁移

Core 提供任务登记、共享目标所有权、完整恢复流程持久日志校验和只处理字节数据的迁移 API。Host 负责身份认证、文件保护、停止执行派发、离线安装和切换；这些 Rust API 不证明 Host 已完成接入，也不提供应用维护命令。知识库来源、检索、查询摘要和完整检查点的接口约定由[知识库 README](../src/recovery/knowledge/README.md)维护。

## 样本与独立故障轮次

`ProblemContext.occurrences` 保存同一故障记录内的异常观察样本数。`RecoveryTask.episode_count` 在任务首次登记时，按相同 `(target_id, fingerprint, conditions)` 的历史不同故障记录/任务数加一；后续任务记录版本保持该值。不同条件分别计数，样本增长或通知重试不增加轮次。

新任务要求绑定可信 `IncidentGuard`，登记时故障必须为当前 `Active` 且记录版本号（`revision`）相同。同一故障记录重复提交返回原任务，包括已经结束的任务，不创建轮次或重新执行。`minimum_script_occurrences` 判断独立故障轮次，约束修复经验保存后的复用资格及当前任务的脚本复用；输入样本数不能扩大复用资格。

格式 1 中缺失或为零的 `episode_count` 从完整历史推导；已有非零值和格式 2 的显式正值必须与可信历史一致。`occurrences` 按输入值保存，无法仅从计数推导可信样本来源；该字段不参与复用阈值判断。迁移不重新计算或扩大已经保存的 `KnowledgeCandidate.reusable` 资格。

## 共享目标所有权

Host 将同一受保护目标的所有别名解析为同一 `CanonicalTarget`，并为相关恢复流程绑定同一 `TargetOwnership` 所有权管理。规范目标必须是小写、长度有上限的稳定逻辑 ID，不能携带路径别名；Core 不解析节点、节点工作区或连接地址。打开恢复流程可进行本地恢复和查询；提交、恢复、推进、核实执行结果和派发执行许可前必须绑定并核验有效的所有权凭据。

`FileTargetOwnership` 用共享所有权目录中的独占文件锁和同步所有权日志，将规范目标绑定到规范恢复流程目录及 `recovery.lock` 文件对象身份。`TargetLease` 实现必须通过 `recovery_directory` 返回该规范目录。不同状态目录或进程不能通过独立任务/审批日志绕过同一目标的所有权限制。进程退出释放操作系统锁，但保留持久日志持有者；原存储可以重新获取所有权凭据，其他存储继续被拒绝，不存在自动到期或强行取得所有权。

正常关闭先停止新执行派发，取消并等待正在处理的调用结束，再确认任务及审批日志没有写入失败造成的不确定状态，文件身份和长度与持久状态一致。只有检查通过、全部任务结束且审批没有 Executing 或 Unknown 时，才显式释放持久所有权。未完成任务、执行不明或不可靠日志保留原所有权，供恢复和核实执行结果；关闭进程不能伪造安全释放。Host 自定义所有权实现须保持同样的独占、存储绑定和持久保留语义。目标所有权不代替审批、执行前故障复核或一次性执行许可。

## 完整恢复流程日志迁移

任务日志保存在 `recovery.jsonl`，保存事件使用格式 2，读取接受格式 1 和 2；恢复后允许在格式 1 历史上追加格式 2，事件格式不能从 2 回到 1，未知格式拒绝恢复。`RecoveryConfig.schema_version` 为 1，与持久日志格式分别验证。完整未关联审批意图按完整方案与操作关联校验。

`validate_recovery_journal(bytes, original_config)` 在原可信配置下验证完整有上限的 JSONL 持久日志，包括总字节、单行和完整换行结尾、格式、连续序号、每行完整配置、任务身份与记录版本号（`revision`）、状态变化、诊断预算、方案/操作绑定、执行和执行结果核实证据。`RecoveryConfig` 没有缺失字段默认值，必需字段不全即拒绝；任务字段仅按其声明使用默认值，未知字段拒绝读取。

`plan_recovery_journal_migration(bytes, original_config, replacement_config)` 支持格式 1 转格式 2，或格式 2 的安全限额调整。允许修改的配置字段只有 `max_tasks`、`max_journal_bytes`、`max_diagnoses` 和 `max_tool_calls`；目标、执行器、Harness、审批规则、操作约定、超时和复用阈值必须保持不变。

新上限必须通过配置校验，不能低于已有任务数、历史诊断次数或完整转换输出字节。迁移保留每个历史记录版本号（`revision`）和序号、审批引用、原 `ProposedOperation`、完整方案、执行回执（`receipt`）、执行结果核实记录（`result_check`）及最终状态；只有持久日志格式、从可信历史推导的缺失轮次数和允许修改的限额可变。输入与输出共用普通任务验证器。

`RecoveryJournalMigration` 返回来源/输出摘要和完整新 JSONL。Core 不安装迁移文件，不截断损坏残片，不补造缺失方案或审批，不重置已经使用的执行许可，不重试已结束任务或自动派发恢复审批后的执行。

## Host 离线维护流程

1. 停止新执行派发，取消并等待正在处理的调用结束，并禁止维护来源继续写入。按[目标所有权](#共享目标所有权)保留仍有未完成或 Unknown 记录的持久所有权。
2. 在受保护的存储上取得可靠来源。恢复流程迁移使用完整字节与原配置；知识库维护按[知识库检查点导出条件](../src/recovery/knowledge/README.md#查询摘要与离线压缩)由仍持写入锁的可靠存储所有者导出。保留关联审批、知识库及目标所有权日志。
3. 验证计划和完整输出，把结果持久保存到新的受保护文件，再重新打开验证。知识库存储所有者关闭后须从已禁止写入的来源重新打开，核对计划的 `source_sequence`、`source_bytes` 和保留事实，确认计划仍对应完整来源。
4. 验证通过后离线切换，并保留原持久日志与配置。读取、写入、重新打开或验证失败时保留原记录，不安装部分输出，不重新执行修复动作。

迁移与检查点仅维护领域持久日志，不实现配置热加载、文件归档策略、跨项目自动同步或真实业务验收。只读查询入口见[恢复流程查询摘要](../src/recovery/workflow/service/README.md)和[知识库查询摘要](../src/recovery/knowledge/README.md#查询摘要与离线压缩)，查询结果不产生授权。
