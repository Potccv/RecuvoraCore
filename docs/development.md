# 开发指南

本指南面向从源码开发或接入 `recuvora-core` 的贡献者，目标是找到修改归属、配置源码外输出目录，并完成与改动相关的检查。领域行为参考从[文档导航](README.md)进入。

## 准备工具链

1. 使用 [rust-toolchain.toml](../rust-toolchain.toml) 指定的 Rust、rustfmt 和 Clippy。包类型、依赖与测试目标以 [Cargo.toml](../Cargo.toml) 为准。
2. 先阅读[项目规范](../AGENTS.md)和[架构](architecture.md)，再从[源码导航](../src/README.md)找到所属模块，阅读该目录及上级的局部规范。
3. 本库没有可启动的应用。接入方通过 Cargo 库依赖调用 API，认证、持久提交、外部能力、调度及运行生命周期由接入方负责。

## 指定输出目录

构建产物和测试运行数据必须放在本库源码之外。运行检查前，为 `CARGO_TARGET_DIR` 与 `RECUVORA_TEST_TEMP` 提供调用方选择的绝对路径；构建目录与临时目录互不包含，已有目录及祖先不能是重解析链接。

检查脚本读取显式参数，不安装工具链或更改全局配置。领域测试仅使用内存；开发脚本测试只删除自己创建的临时子目录；检查结束后只清理本次创建且记录的资源，不清空调用方共享目录。

## 执行检查

按 [Windows 检查说明](../scripts/windows/README.md)从项目根编译并运行 Rust 检查脚本。使用绝对源码路径编译，脚本可执行文件放在源码外的构建目录；执行时传入构建与临时目录参数。脚本参数、完整编译步骤、检查顺序和子进程环境由该说明维护。

开发过程中按[测试与验证](testing.md)选择检查范围。纯文档调整核对 Markdown 链接、目录职责、API 和命令；代码行为变更运行所属目标，交付检查覆盖格式、Clippy、全部单元/集成目标及文档示例。外部目标接入和真实执行验收在集成项目完成。

## 更新文档

根 README 只介绍项目、接入方式与阅读入口。领域细节更新所属模块 README，共同流程更新 `docs/` 中的参考，局部开发约束更新对应 AGENTS；文档职责表见[文档规范](AGENTS.md)。

交付说明应列出实际修改、验证结果和必要限制。不能把本轮未执行的检查或其他环境的验收写成本轮已通过。
