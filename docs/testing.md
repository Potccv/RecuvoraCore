# 测试与验证

本页规定检查选择和证据范围。具体 Cargo 目标与子模块归属见[测试导航](../tests/README.md)，执行入口见[脚本说明](../scripts/README.md)；这里不维护重复的测试清单或按日期排列的验收记录。

## 根据改动选择检查

| 改动 | 开发阶段需要的验证 |
| --- | --- |
| Markdown 文档或规范 | 相对文件与锚点链接、目录/API/配置字段/命令对应关系、格式、单一事实归属和中立示例 |
| 领域政策或状态机 | 所属行为目标；同时检查允许迁移、拒绝路径、当前政策与身份绑定 |
| 持久存储、所有权或迁移 | 同步提交、幂等、重启、单写锁、损坏、容量、写入不确定及 Unknown 保留 |
| 取消、并发或关闭 | 取消并等待正在处理的调用结束、执行结果不明、目标释放条件和恢复后防重放 |
| 完整代码交付 | 现有检查脚本中的格式、全部目标 Clippy、单元/集成测试和文档示例 |

只修改文档时不新增模拟程序测试，也不为了验证文字而重复全套 Cargo 检查。已通过的检查只在相关内容再次变化或仍有未解问题时重跑。

## 测试环境与资源

测试使用假可信端口与中立领域证据，不连接真实 AI 服务、节点、供应商服务或活动部署。运行数据写入外部 `RECUVORA_TEST_TEMP`，构建写入外部 `CARGO_TARGET_DIR`；准备步骤见[开发指南](development.md)。

测试只能清理自己创建并记录的资源。失败排查所需数据可以短期保留，排查结束后按记录范围删除，不能扩大清理范围。

## 证据含义

领域回归证明其覆盖的状态迁移与存储不变量。目标所有权的子进程测试证明测试平台中的进程互斥和退出后归属保留，不能证明外部执行者已经停止。

假后端成功、脚本退出码、文件读回、协议夹具、静态构建和 UI 展示均不足以证明真实业务恢复。跨机部署、进程监督、供应商适配与独立业务验收需要集成项目自己的证据。

执行记录统一保存在[实现状态](implementation-status.md)，标明工具链、执行范围及未验证限制。报告文档测试时区分命令成功和存在可执行示例；环境导致无法执行的检查不能报告为通过。
